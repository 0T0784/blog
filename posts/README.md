# 記事の追加のしかた
1. posts/ に「2026-11-12-好きな名前.md」を作る（先頭の日付が記事の日付）
2. 1行目に「# タイトル」、あとは普通に文章を書く
3. 写真は images/ に置いて ![説明](images/ファイル名.jpg)
4. YouTubeはURLだけを1行で貼る
5. GitHubにpush（posts.json は自動で作られます。手元で確認したいときだけ python make_posts.py）

ブログ名は blog.js の SITE.name、2つのHTMLの <title> で変更。
最初に1回だけ: GitHub → Settings → Pages → Source を「GitHub Actions」にする。

ホームのURLを入れたいとき: blog.js の SITE.home に https://〜 を書く（空ならメニューに出ません）。

# サムネイル
- 何も書かなければ、記事の最初の写真（なければYouTubeの画像）が自動で使われる
- 指定したいときは、記事のどこかに1行「サムネ: images/ファイル名.jpg」と書く（本文には表示されない）
- どれも無い記事は images/default.jpg が使われる（blog.js の SITE.thumb で変更可）

# タグ
- 記事のどこかに1行「タグ: 日常, 音楽」と書く（カンマ・読点・スペースで区切れば、いくつでもOK。本文には表示されない）
- 一覧の上のタグ欄、またはカード・記事ページのタグを押すと、そのタグの記事だけが出る（URL は index.html?tag=日常）
- 「すべて」を押すと、元の一覧に戻る

# 著者とアイコン
- 記事のどこかに1行「著者: ブログ主」と書く（本文には表示されない）
- 著者とアイコンの対応は authors.json に書く。アイコン画像は images/authors/ に置く
    {
      "ブログ主": "images/authors/blogger.png",
      "ゲストさん": "images/authors/guest.png"
    }
- 著者を書かなかった記事は、blog.js の SITE.author の名前になる（空なら著者は出ない）
- アイコンを登録していない（または画像が無い）著者は、名前の1文字目が丸いアイコンになる
- タグは日付の横に出る

# 一覧に出す文章（概要）
- 一覧のカードには、本文は出ない。出したい文章がある記事は、1行「概要: 好きな文章」と書く（本文には表示されない）
- 書かなかった記事は、題名だけのカードになる
- 例: 概要: 2026/11/20 追記あり　新作の情報です

# 更新が反映されないとき
- CSS/JS は開くたびに最新を読み込み、記事の本文も毎回最新を取りにいく仕組みになっている
- push してから公開まで1〜2分。GitHub の「Actions」タブで「Deploy blog」が緑になったか確認する（赤いときは記事一覧が更新されない）

# ヘッダー（TOPページと同じ）
- ロゴ画像は images/logo.png（TOPページと同じ画像）。無いときは blog.js の SITE.brand の文字が出る
- メニューは blog.js の SITE.menu。「#」で始まる行き先は、SITE.home（TOPページのURL）の同じ場所に飛ぶ
- 「お知らせ」タグはタグ欄の一番左（「すべて」の次）、「その他」タグは一番右に出る（blog の index.html の rank で変えられる）

# 画像をGitHubのIssueから持ってくる
- 公開リポジトリのIssueの入力欄に、画像をドラッグ（スマホ・iPadは貼り付け/選択）すると、https://github.com/user-attachments/assets/… というURLができる（Issueは投稿しなくてOK）
- そのURLは、そのまま記事で使える
    サムネ: https://github.com/user-attachments/assets/…
    ![説明](https://github.com/user-attachments/assets/…)
  入力欄に出た「![image](…)」や「<img … src="…">」の行を、そのままコピーして貼ってもOK
- URLだけを1行で貼っても、画像として出る
- 「image」という説明は自動で出さない

# 一覧に出る文章（左上の大きいカード）
- 一覧の左上（いちばん新しい記事）のカードだけ、記事の本文の最初の部分（150文字まで）が出る
- 「概要: …」を書いた記事は、本文ではなく概要が出る（概要は、どのカードでも出る）
- 見出し・画像・URL・「2026/11/20 追記」のように日付で始まる行や、先頭に「追記」「更新」とある行は、本文の抜き出しから外れる
- ほかのカードには、本文は出ない

# 小さいカードに出る文章（追記があるときだけ）
- 左上以外のカードには、基本的に文章は出ない
- 次のどちらかのときだけ、追記の表記が出る
    ・概要に「追記」と書いた（例: 概要: 2026/11/21 追記）
    ・本文に「2026/11/21 追記: …」「【追記】…」のような行がある（複数あれば、いちばん最後のもの）
- 「追記しました」「更新頻度は…」のような普通の文は、追記の表記として扱わない

# 音声ファイル（オリジナルの再生プレイヤー）
- 音声ファイルを audio/ に置く（mp3・m4a・wav・ogg など）
- 記事に1行書く
    音声: audio/曲名.mp3 | 表示したいタイトル     （「| タイトル」は省略できる）
  音声ファイルのURLだけを1行で貼ってもOK
- 標準のプレイヤーではなく、ブログのデザインに合わせた自作のプレイヤー（再生/一時停止、再生位置、時間、消音、再生中に回るレコード）が出る。複数あっても、再生は1つずつ
- ダウンロードについて
    ・標準プレイヤーのダウンロードボタンと、右クリックの保存は出ない
    ・ただし、ファイルのURLは公開されているので、知識のある人が取り出すのを完全に防ぐことはできない（これはどんなサイトでも同じ）
    ・どうしても守りたい音源は、リポジトリに置かない／ビットレートを下げた試聴用や短く切ったものだけ置く、のが確実
- GitHubの1ファイルは100MBまで（50MB超は警告）。サイト全体は1GB程度までが目安

# ダウンロード用のフォルダ
- ファイルを downloads/ に置く（zip・pdf・テキスト・MIDI など）
- 記事に書く（続けて書いたものは、1つのフォルダにまとまる）
    フォルダ: 配布データ                         （フォルダの見出し。省略すると「ダウンロード」）
    ダウンロード: downloads/pack.zip | 素材セット
    ダウンロード: downloads/readme.pdf
- ファイルのURLだけを1行で貼ってもOK（zip・pdf・txt など）
- 同じサイトの中のファイルは、サイズ（KB/MB）も自動で表示される

# GitHubのIssueの添付ファイルも使える
- Issueの入力欄に添付したファイルのURL（https://github.com/user-attachments/files/…）を貼ると
    ・音声ファイル（mp3 など）→ 再生プレイヤー
    ・それ以外（zip・pdf など）→ ダウンロードのフォルダ
  になる。画像・動画の https://github.com/user-attachments/assets/… は、これまでどおり画像として出る
- 他のサイトのファイル（Issueの添付など）は、サイズは表示されない
